# Database (Prisma 6 + PostgreSQL 17)

```bash
cp .env.example .env              # repo root; fill the CHANGE_ME values (never commit .env)
pnpm install
pnpm db:up                        # Postgres 17 on 127.0.0.1:55432 (Redis 16379, S3Mock 19000)
pnpm turbo run build --filter=./packages/*   # seed imports the shared packages
pnpm --filter @670send/api db:migrate        # applies migrations + generates the client
pnpm db:seed
```

## Migrations

| Migration | What it does |
|-----------|--------------|
| `*_init` | Generated by Prisma from `schema.prisma` (tables, enums, indexes, FKs). |
| `*_staged_uploads` | Photos uploaded before the shipment (and waybill) exist. |
| `*_integrity_guards` | Hand-written (copy of `sql/001_integrity_and_immutability.sql`): immutability triggers, deferred double-entry balance trigger, CHECK constraints, sea-route and manifest rules, partial indexes. |

**Never edit an applied migration.** Change the guards by adding `sql/002_*.sql` and a new migration folder
(timestamp **after** the latest one — Prisma applies in lexical order).

In production use `prisma migrate deploy` (never `migrate dev` / `reset`).

## Seed

`pnpm db:seed` is idempotent. Existing rows are kept (so admin edits to tariffs, templates and role grants survive);
`SEED_FORCE_UPDATE=true` overwrites tariffs / templates / settings with the seed values.

* Reference data always runs: RBAC, 14 municipalities, 4 hubs, 4 zones, add-on tariffs, 44 WhatsApp templates, settings, system wallets, bootstrap Super Admin.
* Demo data (3 staff, 2 agents, courier, fleet partner + bus + driver) runs unless `NODE_ENV=production`; force with `SEED_DEMO_DATA=true`.
* In production the seed **refuses to run** without a strong `SEED_SUPERADMIN_PASSWORD` (≥ 14 chars, not the default) and sets `must_change_password`.
* Passwords/PINs are read from the environment and never printed.

## Immutable tables

`ledger_entries`, `ledger_transactions`, `audit_logs`, `shipment_events` reject UPDATE / DELETE / TRUNCATE.
Correct a mistake by posting a reversing entry, never by editing history.
(`prisma migrate reset` still works in development because it drops the schema.)
